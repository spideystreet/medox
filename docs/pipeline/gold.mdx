## Overview

The Gold layer converts Silver SQL tables into dense vector embeddings stored in **Postgres** (`pgvector`) for semantic search. The `gold_embeddings` Dagster asset fills `gold.embedding`.

## Embedding Model

Medox uses a **local** HuggingFace model — no external API calls, no data leaving the machine.

| Setting | Value |
|---------|-------|
| Model | `intfloat/multilingual-e5-base` (default) |
| Library | `sentence-transformers` |
| Dimensions | 768 |
| Distance | cosine (`<=>`) |
| API cost | Zero — runs entirely on local CPU/GPU |
| Download | First use only — cached in HuggingFace cache directory |

The model is configured via the `EMBEDDING_MODEL` environment variable. Passages are stored with a `passage:` prefix. Queries are prefixed with `query:`.

## Indexes

Both indexes are rows in `gold.embedding`, distinguished by `collection`.

```
idx_<source>_<content>_<model_version>
```

| Collection | Source | Content |
|------------|--------|---------|
| `idx_bdpm_medicament_v1` | `silver_bdpm__medicament` + `silver_bdpm__composition` | Drug specialties with composition |
| `idx_ansm_interaction_v1` | `silver_ansm__interaction` | Drug interactions with constraint levels |

`pipeline/io/builder_documents.py` builds the `(ids, documents, metadatas)` tuples. Embeddings are written in one transaction per collection, so a rebuild replaces the index only after the new vectors exist.

The HNSW index uses `vector_cosine_ops` (`m = 16`, `ef_construction = 200`). Queries set `hnsw.ef_search = 128` and drop matches farther than cosine distance `0.42`.

Postgres must be the `pgvector/pgvector:pg16` image. `CREATE EXTENSION vector` runs when the gold asset or a search first touches the table.

## Metadata

- **Medicament index**: `cis`, `etat_commercialisation`
- **Interaction index**: `substance_a`, `substance_b`, `niveau_contrainte`

A numeric query to `search_drug` filters on `cis`.
